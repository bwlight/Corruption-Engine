# Security Policy  
_For the Corruption Engine Project_

## 1. Supported Versions
Corruption Engine is currently in active development.  
Security updates apply only to the **main** branch.

Once versioned releases begin, this section will list which versions receive security patches.

---

## 2. Reporting a Vulnerability

If you discover a security issue, please report it **privately**.

### How to report:
- Open a **private security advisory** on GitHub  
- OR contact the maintainer directly through GitHub profile email (if available)

Please include:
- A clear description of the issue  
- Steps to reproduce  
- Potential impact  
- Any suggested fixes (optional)

**Do not** open a public issue for security vulnerabilities.

---

## 3. Responsible Disclosure

To keep users safe:
- Please allow the maintainer reasonable time to investigate and patch the issue  
- Do not publicly share exploit details before a fix is released  
- Coordinated disclosure is appreciated

---

## 4. Scope of Security Concerns

This project welcomes reports related to:
- Code vulnerabilities  
- Data handling issues  
- Unsafe dependencies  
- Logic flaws that could compromise user experience or device stability  

Out of scope:
- Feature requests  
- Gameplay bugs  
- Typos or minor UI issues  
(These should be submitted as regular issues.)

---

## 5. Security Expectations

The project aims to:
- Avoid unsafe dependencies  
- Keep user data local and private  
- Maintain a stable, offline-first experience  
- Patch vulnerabilities promptly once identified  

---

## 6. Acknowledgments

Security researchers and contributors who responsibly disclose issues may be credited in release notes (optional and with permission).
